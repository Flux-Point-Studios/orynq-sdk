# Conduct circuits (prototype)

Prototype: not deployed, ABI not frozen. These Compact 0.31.1 sources ship under `circuits/conduct` but nothing in the package entry exports or loads them. They port the conduct verdict of `@fluxpointstudios/orynq-sdk-conduct`'s runtime guard into compiled circuits, and open the bytes the producers hash, process-trace guard events and conduct mandate CBOR, so both can be compared with the runtime before any proof statement is frozen. A per-step prototype composes them: for one guard event it shows that the decision the guard recorded is the verdict over the event's own action, the atoms under a mandate-atoms commitment, an allowlist path and a stated prior spend.

## Files

| File | Content |
| --- | --- |
| `verdict_core.compact` | `module ConductVerdict`: `evaluate` (11 inputs, `asset_ok` as a Boolean) and `decide`, which adds the guard clock |
| `predicate.compact` | pure `evaluate` over the slice-1 12-slot `PREDICATE_LAYOUT`, pure `guard_verdict(enforced_at, ...12)`, and the provable `check_verdict(enforced_at, ...12, claimed)` that writes `verdictOut` to the ledger |
| `templates/guard-event-v1.json` | the single byte template of a guard event's process-trace preimage: constants and value segments in canonical key order for payments and egress, the denial fields and the seven denial reasons with their rule strings |
| `classes.json` | the compiled classes: for the `openings` unit, five event classes (kind and value lengths) and six mandate classes (text lengths and uint head widths); for the `steps` unit, ten step classes (kind, value lengths, the CBOR head widths of the action's uints, and the allowlist depth where the decision reads a membership path) |
| `gadgets.compact` | `module ConductGadgets`: decimals, escape-free and any well-formed UTF-8, lowercase hex, uuid and ISO shapes, visibility, base58, printable ASCII and CBOR uints; for the steps, the hex of 32 bytes, one level and the fold of a conduct allowlist path, and the spend window of an action time and its guard clock |
| `openings.generated.compact` | generated by `compile-conduct.mjs --write` from the template and classes through `scripts/conduct/template.mjs`: one `ev_*` circuit per event class, one `m_*` circuit per mandate class, and a pure probe of each lexical gadget, of each decimal gadget at every width a class reads it at, and of each CBOR uint width |
| `steps.generated.compact` | generated the same way: one `st_*` circuit per step class, and pure probes of the path gadget at depths 1 to 6, of the window gadget and of the byte-hex link |
| `mutants.json` | one-edit discrimination mutants of the predicate, openings and steps units, and one recorded equivalent mutant, each compiled from its own edited sources in `conduct-managed/mutants/<id>/source/`. A mutant of a source two units compile names its unit |
| `reference/poac_verdict_core.compact` | PoAC's verdict core wrapped as a 12-argument contract. It ships in the package only as the explicit-time test oracle of the mutant tests, is built as its own `reference` unit, pins nothing and is never deployed |
| `pins.json` | toolchain, source hashes, and for every provable circuit its ZKIR hash, k, rows and an op histogram |

`node scripts/compile-conduct.mjs --check` (run by `build:conduct`) first regenerates `openings.generated.compact` and `steps.generated.compact` and refuses a committed copy that differs. It then compiles the `predicate`, `openings`, `steps`, `mutants` and `reference` units into the gitignored `conduct-managed/` and mock-compiles the ZKIR of the predicate, openings and steps units and of the predicate mutants, at most one compiler or zkir process per CPU. The openings and steps mutants are judged by their generated JS, the openings mutants also by the private inputs their compactc ZKIR takes, and are not mock-compiled, except a mutant that `mutants.json` marks with `"zkir": true`: `step_no_recorded_decision`, the ZKIR control of the step tests. When one compile fails, the script lets the others finish and removes their scratch before it exits. It recompiles `predicate.compact`, `openings.generated.compact` and `steps.generated.compact` with every pure circuit unexported and refuses any difference in the provable circuits' ZKIR; `pureExportInvariant: true` is written only after that comparison passed, so the assurance is the refusal, which the tests exercise for each of the three units with a compiler that perturbs the unexported compile. It then requires the rebuilt pins to equal `pins.json` byte for byte. `--write` regenerates the openings and steps and rewrites the pins. The script takes only `--check` or `--write` and one optional `--units` list, and for these units reads only files the npm package ships. `--units bench` or `--units bench:<group>` instead builds the bench circuits of `bench/conduct/bench.json`, which only the repository holds, and holds them to `bench/conduct/pins.json`; a run takes the units or the bench groups, never both (see Measurements). Each compiled unit's source map is rooted at the sources it was compiled from, with compactc's built-in standard library marked virtual.

CI builds and tests the conduct circuits in their own `conduct-circuits` step, which runs after `build-test` and beside `midnight-submit`: `build:conduct`, then the conduct suite through `packages/midnight-prover/vitest.conduct.config.mts`, which takes the root config's aliases and includes only `tests/conduct`. The root vitest config excludes `tests/conduct`, so `build-test` never runs the suite without the circuits it reads. `build-test`'s root run does collect `tests/conduct-ci.test.ts`, which reads only `ci.yaml`, the package scripts and the two configs. It fails CI if the `conduct-circuits` step is removed or moved out of the pipeline's `steps` list, gains a `when`, `failure` or any key beyond its image, dependency, environment and commands, or changes those; if a conduct test is skipped, pending, focused or marked as expected to fail; and if the conduct config gains any setting that could drop a conduct test file. The span-tree test (T-C07) builds its own bench group with `--check --units bench:span` before it runs, so the same step holds that group to its pins. Locally:

```sh
pnpm --filter @fluxpointstudios/orynq-sdk-midnight-prover build:conduct
pnpm exec vitest run --config packages/midnight-prover/vitest.conduct.config.mts
```

| Statement | Disclosed (ledger) | Tied in-circuit to hashed bytes | Assumed | Refused |

The event's amount, times, parties and digests are not disclosed by a step | the canonical event preimage and the rolling step, as S-EVENT-OPEN; the action digest recomputed from the event's own action bytes and held equal to its `actionDigest` hex (D6); the event's `mandateCommitment` hex decoded into K's preimage, so the disclosed K is over that commitment and the atoms the verdict reads; the action time and guard clock in one spend window of the atoms' width, whose quotient is `windowIndex`; `asset_ok` from the SHA-256 of the event's asset bytes against the atoms' asset digest; for an allowed action and a spend-cap denial, a path from the leaf of the event's own counterparty or destination to the root in the atoms; `verdict = decide(...)` over those and the disclosed `priorSpent`; and that verdict equal to the decision the class's event type and reason record | A1 to A5 below | bytes outside the class; an action later than its guard clock or in another spend window; a verdict of 5 or 7 (`non-membership not provable`): an off-list denial is refused, never proven and never read as a breach; any verdict other than the recorded decision |

Assumptions of S-CONDUCT-STEP, each public and none shown by the circuit:

- A1. `priorSpent` is the spend the guard had accrued in the mandate's window `windowIndex` before this event. A step circuit accepts its verdict for the prior it states; any prior with the same verdict is accepted as well, which the tests pin as a gap. A committed spend state is later work.
- A2. `prevRollHex` is the lowercase hex of the previous step's `rollAfter`, or the genesis hash. `statement-checker.ts` checks it outside the circuit.
- A3. The last `rollAfter` reaches an authenticated anchored root, which also needs the trace's span hashes and manifest hash.
- A4. A verified S-MANDATE-OPEN discloses the same K. Then the atoms a step read are those of that mandate's own bytes. `statement-checker.ts`'s `weld()` checks the equality outside the circuit; a step alone shows only that its verdict used the atoms under the K it discloses.
- A5. The allowlist has at most 2^D members for the class's depth D, and the event is in a compiled class; otherwise classification refuses it.

## Claims

C1. On the inputs below, the compiled verdict agrees with the runtime guard. Its inputs are not authenticated at this layer. `guard_verdict`'s agreement is conditional on the D12 preconditions: the runtime refuses a step that breaks one of them, and `guard_verdict` cannot see them.

The evidence has two legs that hold together (AM-6): an audit of the sources' structure, and an exhaustive differential over the space that structure leaves open.

- Structure (T-A16, `predicate-structure.test.ts`). The audit parses `verdict_core.compact` and `predicate.compact`, refuses a file it cannot read to the last token, and requires exactly the audited structure, which `tests/conduct/structure.ts` lists. It reads only printable ASCII and newlines: compactc also ends a line comment at a carriage return, U+0085 or U+2028, and would read the rest of that line as code.
  - each file's declarations in order: the pragma, imports, include and ledger field verbatim, and each module and circuit by name, so a constructor, a struct, another module or another import is refused;
  - the 16 numeric literals: the verdict codes 0–7, the kind and mode tests, the domain bounds and the amount floor;
  - the 15 comparisons, each with its operands;
  - each circuit's signature, its calls with their arguments, and its decisions in order;
  - in the compiled contract, one generated method per audited circuit beside compactc's constructor, initial state and `==` helpers. compactc parses the sources on its own, so a circuit the audit's parse never reached still shows here.

  Only `ConductVerdict`'s conditions may differ from the audited text, and only by combining audited comparisons and Boolean inputs with `!`, `&&` and `||`. `check_verdict`'s condition, that the claim equals `guard_verdict`'s verdict, is audited verbatim. An edit that adds, removes or re-pairs a literal or a comparison, adds or moves a declaration, changes a signature, a call or `check_verdict`'s condition, or moves a decision fails with an exact message. The test shows this for a band between 2^32 and 2^53 on the cap rule, a comparison of the action time with the cap, the 4/5 rules swapped, a waiver module rebound to `CV_` behind a constructor, a struct or carriage returns in line comments, a second module rebound to `CV_` from the other file, and a `check_verdict` that accepts any claim, or refuses every claim, for an action off both lists.
- Order types (T-A17, `predicate-order.test.ts`). The cells take all 75 weak orderings of `notBefore`, `notAfter`, the action time and the guard clock at three scales:
  - 0 to 3;
  - Unix times a day apart around 1.7e9, with amounts, priors and caps between 2^32 and 2^53, where lovelace amounts lie;
  - the top of uint64, the latest time at 2^64−1 and the others 2^32 apart below it.

  They cross each ordering with action kinds 0, 1, 2 and 255, egress modes 0, 1, 2 and 255, every relation of prior spend plus amount to the cap, amounts of 0, 1 and a mid value, priors of 0, a mid value and 2^64−1 where the runtime can hold it, and every asset, counterparty and egress membership: 501,120 cells.
  - Each cell is judged by the runtime guard through its own code path: a guard built from the cell's mandate, an allowed payment opening the spend window where the runtime can hold the prior, then the action under the cell's clock.
  - `evaluate` must equal `MandateGuard.evaluate` and `guard_verdict` must equal `MandateGuard.enforce`, and each must refuse wherever the runtime refuses: an empty validity window, a mode or kind outside {0, 1}, a zero payment, or an action later than the clock. A refusal must name one of the asserts whose condition the cell's inputs break, and the runtime's own refusal must be one of those same asserts. Where only one assert applies, the circuit must raise exactly that one; where several apply, any of them is accepted. Every cell agrees.
  - Slots the runtime has no input for take the decision of the action it can take: a payment's egress membership; an egress's asset, amount and counterparty membership; egress membership under deny-all; and a prior the runtime cannot hold before an egress. A payment after a prior the runtime cannot hold, because no allowed payment can precede `notBefore` or the clock, is judged as one payment of the total.
  - A coverage test shows that the cells meet every truth assignment of the audited comparisons and Boolean inputs that any input can produce. Comparisons that share no input are independent, and each group's reachable assignments are found by brute force.
  - So an edit that passes T-A16 and changes a verdict or a refusal of `evaluate` or `guard_verdict` on any input disagrees with the runtime on a T-A17 cell. Such an edit leaves `check_verdict`'s condition as it is.
- T-A17 ZKIR leg. For each decision path (ten verdict paths and five refusals) at each scale, the sample takes the first cell to which no other refusal applies, and also the first such cell after a spend: 81 cells. `check` accepts exactly the runtime verdict and discloses it, and refuses every claim for a refused cell. The sample checks the compiled constraints against the runtime. T-A16 confines what an edit can change.
- Named sets, at the generated-JS layer. `evaluate` equals `MandateGuard.evaluate` and `guard_verdict` equals `MandateGuard.enforce` on:
  - all 17 predicate-vector cases (23 steps) and all 24 guard-vector sequences (31 steps);
  - the clock cases and all 144 matrix combinations;
  - the uint64 boundary and widened-sum cases, and the Unicode and asset cases;
  - 43 spend-window cases, 41 of which follow an allowed payment in the same spend window;
  - 103 range steps, at the bottom of uint64, at Unix times in one day's spend window and at the top;
  - 1,000 generated two-step guard histories with small values, and 2,000 drawn across uint64.

  Before every step the harness's per-window spend model equals `guard.spentInWindow`. 115 actions are later than the guard clock, and the runtime and `guard_verdict` both refuse them: 12 clock cases, the 32 late matrix actions, 24 range steps, their 24 invariance flips and 23 spend-window cases.
- Three more named sets hold inputs the runtime cannot take, so each names its own judge:
  - Invariance cases change an argument the verdict must ignore and expect the unmodified action's runtime decision.
  - Over-cap prior cases set `prior_spent` above the cap, which the runtime never holds, and expect the runtime's decision on a fresh payment of the same total.
  - The 258 out-of-domain cases set an empty validity window, an action kind or egress mode outside {0, 1}, or a payment amount of 0. Both circuits must refuse them.
- ZKIR on the named sets (`check_verdict`, which is `guard_verdict`). On every named case except the generated histories, `check` accepts exactly the expected verdict and the transcript discloses it as `verdictOut`.
  - Every other claim among the codes 0–7 and the out-of-table values 8, 128 and 255 is refused, and for one case of each verdict code every other `Uint<8>` value is refused.
  - None of the 373 refused named cases has a claim that checks.
  - On the fixture steps, the honest input under another claim's ledger write is refused.
  - Of the histories drawn across uint64, every 50th step (80 steps) is checked against every claim.
- The 12-argument `evaluate` is a pure circuit and has no ZKIR. Its explicit-time expiry (`action_timestamp >= not_after`) is evidenced only at the JS layer: inside `check_verdict` the clock rule already returns 2 whenever the action is at or past `notAfter`.

ZKIR `check` executes the compiled IR on the supplied input. It shows the compiled constraints reject a forgery; it is not proof verification.

C2. Within a compiled class, an opening circuit's disclosed values are functions of exactly the bytes that process-trace and conduct hash. The circuits refuse bytes outside the class and never read them as a nearby in-class value.

- Single source. `templates/guard-event-v1.json` expands to the 11 guard event kinds: payment and egress actions, payment denials 1–5, and egress denials 1, 2, 6 and 7. Thirty-three real events cover every kind in three shapes, from ASCII-minimal to values near the top of uint64. Each is enforced through `MandateGuard.enforceAsync` with a sink that appends to `MemoryGuardLog` and then `processTraceSink`. For each, `render(classify(e))` is the preimage process-trace hashes, byte for byte, and its SHA-256 is `computeEventHash(e)` (T-B01, T-B02). Five hundred seeded generated in-class witnesses, with 4-byte UTF-8, U+2028, DEL and a leading BOM, re-canonicalize to themselves and parse back to the classified values (T-B05). The template must declare each value in the lexical class, and the payment amount with the floor, that `VALUE_CLASSES` in `tests/conduct/openings.ts` commits from S-EVENT-OPEN; a template without the floor, or with the trace sequence read as any uint64, fails T-B01 with an exact message.
- One split. Constant segments fix key order and delimiters. Strings exclude the quote and backslash, decimals are digits only, and hex, uuid, ISO time and visibility have fixed shapes, so no other split of the same bytes fits the class.
- One read. A second read of a witness is a private input of its own that the hashed bytes do not bind, so a disclosed value or a hash input taken from it could differ from the hashed bytes. The test witnesses refuse a second read of any witness in one circuit run, so a circuit that reads one twice fails every honest control in the generated JS and at ZKIR, whose `check` replays the private transcript of that JS run. Each event and mandate circuit's compiled ZKIR takes exactly one private input per witness byte of its class, a width the test derives from `classes.json` alone (T-B19).
- Structure (AM-8, `openings-structure.test.ts`). The audit in `tests/conduct/structure.ts` parses `gadgets.compact` and `openings.generated.compact` to their last token, reading only printable ASCII and newlines.
  - `gadgets.compact`: its declarations in order, and each gadget's literals (every numeric and Boolean literal of its body, its types' included), comparisons with their operands, calls with their arguments, and signature and statements in order, as `structure.ts` commits them.
  - `openings.generated.compact`: its declarations in order, since the order of the ledger declarations sets each statement cell's transcript slot, and each class's literals, comparisons, calls with their widths, witness reads, ledger writes and statements in order, against the text `tests/conduct/opening-reference.ts` writes for every class in `classes.json` and every gadget probe without the template, its emitter or its renderer. The reference takes an event's preimage from a real guard event of its kind, canonicalized as `computeEventHash` canonicalizes it, checked against the event's hash and split at its values, and the values each action opens, in order, from that preimage. It takes each value's lexical class and the amount's floor from `VALUE_CLASSES`, so a template edit cannot move what a class is held to. It writes a probe for each CBOR uint head width, for the string gadgets at one to four bytes, for `decU64` at every width a class reads a decimal at and `dec53` at every width a class reads a trace sequence at, and for each fixed-shape gadget. It takes the rolling and leaf domains from process-trace and conduct, and a mandate class's CBOR from the codec's encoding of a mandate of the class's dimensions, which it checks against `encodeMandate`. So each class reads each witness exactly once and writes one ledger cell. A `persistentHash` call that lists one type per input is compared by the bytes it hashes, and any other as written. compactc encodes each input at the type its type list gives, widening an input to a wider type, so each input is compared with that type. A constant joins its neighbours in one run of bytes only under the type compactc gives the literal: `Bytes<n>` for a string of n bytes, `Vector<n, Uint<8>>` for n byte literals. A string is a constant only if its sole escapes are `\"` and `\\`, since compactc encodes a string as UTF-8 and writes `"\u00ab"` as two bytes.
  - The compiled contract implements exactly the audited class circuits, probes and witnesses, and no method beside them, the gadgets and compactc's helpers.

  An edit that adds or changes a literal, a comparison, a call, a hash input's type, a witness read, a ledger write, a statement or a declaration fails with an exact message. The parser binds `as` and the comparisons as compactc does: `a + b as T` casts the sum, and `a == b < c` compares `a` with `b < c`. Like compactc, it refuses a list of arguments, tuple items, parameters or type arguments without the comma between two items. The test shows this for `decimal_leading_zero_waived_for_nines`, which waives the leading-zero rule for decimals of three or more digits ending in 9, and `cbor_uint_minimal_waived_at_1000`, which accepts a CBOR uint of 1000 at any width. It also shows it for:
  - in a class: an amount waiver at 1000, a payment class without its amount floor, a string gadget behind `if (false)`, another rolling domain, a party leaf hashed as 16-bit words or with no type list, a mandate atom hashed as a field element, and `"\u00ab"` in a mandate commitment's constant bytes;
  - in a gadget: an assert turned into a binding nothing reads, arithmetic outside every call and comparison, a reordered returned tuple, a comparison moved between asserts, a literal moved into a binding nothing reads, `&&` turned into `||`, an added binding and an added declared type, and the two precedence readings above;
  - in a probe: a string probe retargeted to the other UTF-8 gadget, a `dec53` probe read through `decU64`, and a decimal probe read at another width;
  - a pure circuit that is not a probe, a witness and a circuit outside every class, a carriage return in a gadget comment, and an event class written from a miswritten template that the template's renderer agrees with.

  Every openings mutant in `mutants.json` fails the audit.

  AM-8 sets the bar: an opening mutant counts as a finding only if it passes this audit, and one that passes it and survives the byte-mutation and forgery suites is a HIGH finding. Every statement of a gadget, a class and a probe is compared in order, so a passing edit can only change layout: whitespace, comments, redundant parentheses and braces, and how a hash's constant bytes split into literals. T-B18 and the byte-mutation and forgery suites test the circuits' behaviour beside it.
- Event openings (T-B06–T-B11, T-B18):
  - Each class opens two honest events and discloses what the product computes: `computeEventHash` and `updateRollingHash` for the rolling fields, `allowlistLeaf` for the party leaf. In four classes the guard wrote them through `enforceAsync`. No guard log reaches a 20-digit position, so the two `ev_pa_max` events are built by hand; the trace sink validates each with the producer's own snapshot before process-trace hashes it.
  - Every witness byte moved by one is refused: 3,732 changes over the five classes. Every segment has a rejection from the event-hash link, and a segment of another length is refused by the generated binding.
  - Every eventHex byte is forged with `rollAfter` re-derived over the forged hex, so only the hex link can refuse: another hex digit, which the link's equality refuses, and for a letter the non-hex byte that `nib` reads as the same nibble (`:` for `a`), which only its hex check refuses. All 64 positions are refused in every class.
  - No two statement fields of an honest opening hold the same value: the guard clock runs a second ahead of the action and the trace sequence apart from the guard log position. So a field read from another segment's bytes is refused. Every statement field moved by one is refused, and so are the bytes of one event under the statement of the other in the same class.
  - Each lexical gadget refuses its out-of-class bytes with the event hash, the rolling step and the statement re-derived from them, so nothing else can refuse. That covers malformed UTF-8 and all 34 JSON-escaped bytes in each of the nine string segments of the compiled event classes, which the test derives from `classes.json`, the template's value names and `VALUE_CLASSES`: overlongs, a surrogate, leads above F4, lone and misplaced continuation bytes and truncated sequences. Every decimal, hex, uuid, ISO and visibility segment of every compiled class, derived the same way, refuses a leading zero, the bytes on either side of the digits and of the lowercase hex letters, a zero amount in every payment class whose amount is one digit (a wider zero has a leading zero), the digits of 2^64, 2^53 and an exponent as trace sequence, uppercase hex, and malformed uuid, ISO and visibility values. The test counts these forgeries per class, and also the 35 that a segment's width cannot hold, such as a leading zero in one digit. DEL, U+2028 and a leading BOM open.
  - Each lexical gadget's pure probe agrees with a reference on the inputs below (T-B18).
    - The string gadgets are judged by the WHATWG decoder in fatal mode, and the escape-free one also by `JSON.stringify`. The UTF-8 automaton compares a byte only with its 16 audited byte literals, which split the bytes into 29 classes: each literal alone, and each run between two. Every bound of Unicode Table 3-7 and of JSON's raw bytes is a class bound too, so the automaton and its reference judge every byte of a class alike. The inputs are every one- and two-byte string and every sequence of three and four classes: the lowest and highest byte of each class at three bytes, the lowest at four.
    - The decimal gadgets are judged at every width a class reads them at: `decU64` at 1, 2, 10, 16 and 20 bytes and `dec53` at 1 and 16. They take every input of up to two bytes. At wider widths they take every byte value at every position of the width's smallest and largest values, of a value with a leading zero, and of 2^64−1 or 2^53−1 where the width holds it.
    - The hex, hex-link, uuid, ISO, visibility, base58 and printable-ASCII gadgets take every byte value at every position of an in-class value.
  - The same JSON hashed under another domain never opens.
  - At the ZKIR layer, `check` runs on copies of the generated JS with every assert a no-op and every narrowing cast unchecked, so no JS check refuses a forgery first. It accepts each honest opening and discloses its statement. It refuses every statement field moved by one, a forged amount or time, a forged party byte under the true leaf, a quote in a string and the last event-hash hex digit forged in every class. It also refuses every eventHex forgery of `ev_pa_ascii_min` and `ev_ea_ascii_min`, the malformed UTF-8 and escaped bytes in a counterparty, and every lexical forgery of a decimal, hex, uuid, ISO or visibility segment in the first class that holds it. Each has the rest of the opening re-derived.
  - A forgery whose value leaves its field's type keeps the field's honest value in the statement, and also runs at ZKIR in the first class that holds it. Each of the 20 digits of 2^64 in a decimal is refused by the `Uint<64>` cast's bit bound, before any lexical assert, with `Bit bound failed: 000000000000000001 is not 64-bit`: the amount in `ev_pa_unicode_max`, and the time, guard clock and data sequence in `ev_pa_max`. `/` in a one-digit decimal, `:` as the last digit of 2^64−1 and an uppercase letter that takes a digest half past 128 bits are refused by their lexical asserts. ## Refusals shared with the runtime

The circuits refuse three inputs that the runtime schema also refuses and that PoAC gave a verdict:

- an empty validity window, which the runtime refuses at mandate construction (`SCHEMA_BAD_VALIDITY`). The `not_before < not_after` assert follows from AM-6.2, which requires the circuits to refuse what the runtime refuses;
- action kind and egress mode outside {0, 1} (D2), where PoAC interpreted any non-zero kind or mode;
- a payment amount of 0 (AM-2), which the runtime refuses as `SCHEMA_BAD_AMOUNT`.

## Divergences

The slice plan and the decision owner's rulings declare these differences from the runtime:

- The 12-argument `evaluate` has no clock (D1). With a guard clock at or past `notAfter` and an earlier action time, the runtime denies `MANDATE_EXPIRED` and `evaluate` judges the action time. `guard_verdict` follows the runtime.
- Asset equality is tag equality. The circuits compare `assetTag` values, bytes 1–31 of an undomained SHA-256 of the asset (248 bits), where the runtime compares strings. The two agree only while that truncated hash resists collisions. This holds for `evaluate`, `guard_verdict` and `check_verdict`; a step compares the full SHA-256 of the event's asset bytes with the asset digest under K.
- D12 (AM-3): three runtime refusals are preconditions on guard state. A pure verdict over one step cannot see prior calls or the window width. `guard_verdict`'s statement is conditional on them, and the tests pin that it returns a verdict where the runtime refuses:
  - a guard clock that moves backward;
  - an action time that moves backward;
  - a guard clock in a different spend window from the action.

  The step circuits hold the same-window precondition themselves, through their window witness (T-C02). Monotonicity of the clock and of the action time needs a committed predecessor state, which is later work; no step shows it.

## Non-claims

- Authenticity of any verdict input at the predicate layer. `counterparty_ok`, `egress_ok`, `prior_spent`, the asset tags and the mandate fields of `evaluate`, `guard_verdict` and `check_verdict` are caller-supplied; the negative controls show a false prior spend or a flipped membership Boolean changes the verdict. A step computes membership and the asset rule itself and reads the atoms under K, and still takes `priorSpent` as stated (A1).
- A chain position for an opened event. That `prevRollHex` continues the chain from the genesis hash, and that `rollAfter` reaches an anchored root, are assumptions checked outside the circuits.
- A link between an opened event and a mandate in the opening circuits. K is computed in-circuit from C and the opened atoms, and carries no authority. A step ties its event to the atoms under the K it discloses; that those are a mandate's atoms rests on a verified S-MANDATE-OPEN of the same K (A4), and that the mandate was issued by anyone is outside these circuits.
- Any meaning for an event's id, trace timestamp or visibility. They are opened only lexically and appear in no claim.
- A link between an opened event's `actionDigest` and its disclosed action fields in the `ev_*` circuits, which open `actionDigest` and `mandateCommitment` only as lowercase hex. The step circuits recompute the action digest from the opened action (D6).
- Privacy. Amounts, times and identifier digests are disclosed, and guessable values can be recovered from them.
- Cumulative or whole-run compliance, and the authenticity of any root, checkpoint, sequence or epoch. A step is about one event under a stated prior spend; that the steps of a run are complete, ordered beyond A2, or reach an anchored root is not shown. Both sequences a step discloses, the guard log position and the trace sequence, are stated; which is authoritative is not decided here.
- Non-membership: an off-list verdict is refused, never accepted by a step circuit, and is not a breach. A missing proof says nothing about conduct.
- Anything about process-trace's span tree. The option B circuits are bench measurements against the existing tree, whose root commits neither a leaf count nor an index.
- Proof validity from simulation. No key or proof ships with these circuits, and no JS simulation or ZKIR `check` shows one would verify. Only `measure.mjs`'s native-verifier results count as proof evidence, they exist only for the circuits a run keyed, and no step circuit is among them.
